# PDF阅览与批注助手 1.1.0

通过本机 PDF 库、页面图片预览和逐批确认完成 PDF 审阅。新增高亮、便签、印章，填写真实表单，放置签名图片，最后另存并校验副本。

本版修复 1.0.0 在 WorkSwarm 中“工作目录不可读”和“查看器未连接”的问题：明确指定工作目录，直接操作本地文件。无需 Node.js、npx、MCP 服务或 MCP App 查看器。交互方式是页面 PNG 预览与确认，不提供实时拖拽查看器。

## 安装

1. 在 WorkSwarm 扩展面板更新/导入 `pdf-viewer-1.1.0-native.zip`。归档根目录含 manifest.json；不要使用市场包装 ZIP 做本地导入。
2. 确认插件卡片版本为 1.1.0，新会话选择本插件。工具名为 `pdf_review`，旧的 `mcp_pdf-viewer_*` 工具不属于新版。
3. 需要 Python 3.10+ 及 requirements.txt 中的四个依赖。先调用 `status` 检查；工具加载本身不导入这些依赖，因此缺依赖会返回中文提示，而不是导致整个插件消失。
4. 如果缺依赖，使用准备运行本插件的 Python 安装：`python -m pip install -r <插件目录>/requirements.txt`。工具不会自动安装或联网。
5. 如有多个 Python，可将环境变量 `WORKSWARM_PDF_PYTHON` 设置为已安装依赖的 Python 可执行文件绝对路径，然后重启 WorkSwarm。冻结打包的 workswarm.exe 不会被误当成 Python 执行。

## 使用

所有文件都放在用户当前工作目录，调用时明确传 `workspace_dir` 绝对路径。相对文档路径以该目录为基准；中文路径、空格和普通 Windows 绝对路径可用。不需要 MCP roots，也不要改写旧版 MCP 配置。

示例：

- “使用 PDF阅览与批注助手，检查依赖，列出当前工作目录里的 PDF，打开 sample.pdf 并展示第一页预览，先不修改。”
- “把‘付款期限为收到发票后 30 天。’高亮，在右侧加便签‘请复核’，生成修改计划与预览，等我确认。”
- “确认应用刚才这个计划，然后另存为 sample-annotated.pdf。”
- “打开 test-form.pdf，检查真实字段，把姓名填为测试用户，邮箱填为 pdf-test@example.com，先给我预览再应用。”

`open` 返回 review_id 和 revision。`plan` 返回 plan_id、变更清单和候选预览，但不替换当前版本。用户确认后 `apply`；`save_as` 重新打开检查后返回实际路径和 SHA-256。预览 PNG 可用宿主的文件查看工具展示；具体参数见 Skill。

工作目录中的 `.pdf-review/` 保留快照、计划、版本和预览，方便继续修改与删除本次新增的批注。不要在审阅过程中删除此目录。导出的 PDF 可以独立打开；印章、自由文字和签名图成为页面内容，继续撤销或修改这些叠加应使用原审阅 ID。

## 限制

- 不覆盖原稿或已有文件；另存时选择新文件名。
- 单个文件最多 50 MiB / 1000 页；每批最多影响 4 页，每次预览最多 4 页。
- 扫描 PDF 没有可搜索文字时不能自动文字高亮；可使用用户核对过的矩形位置。不提供 OCR 或摘要。
- 签名只放置 PNG/JPEG 图片，不是密码学数字签名。已有数字签名/认证的 PDF 仅允许查看，不修改。
- 表单保持可编辑；不以页面文字冒充字段填写。加密、歧义表单及不支持控件会明确报错。
- 不直接下载 URL 或远程图片；先用宿主下载到已指定工作目录。
- 1.1.0 为独立实现，1.0.0 的用户测试和截图不代表新版通过。仍需在 WorkSwarm 测试本版。
