# 项目资料导航 1.0.0

面对“先看哪些项目资料”这个问题，根据明确任务生成主要、支持、关联资料三层结果，提供路径、命中行、引用关系与内容指纹。也可固定资料、排除旧文件，核对本插件读取之后文件是否变化。

## 安装与第一次使用

在 WorkSwarm「扩展 → 我的扩展」导入本地测试包 `project-context-1.0.0-workswarm.zip`，点击使用或新建对话选中「项目资料导航」。把 ZIP 附在聊天中不等于安装插件。仓库交付 ZIP 另含 marketplace 外层，不与本地导入 ZIP 混用。

运行要求：macOS/Linux、Python 3.9+、已有 Node 20+。macOS 优先使用 WorkSwarm 自带的 Node；其他平台使用 PATH 中已有 Node。运行仅用两者标准库，没有 npm/pip 依赖，无需激活 Conda或手动初始化。未找到兼容运行时会报告错误，不会自动安装或升级。Windows 未支持。

发送：“请实际使用项目资料导航，创建一个独立演示项目，再查询‘登录设计 tokenlogin 离线缓存’，展示工具返回的资料包、路径和命中行。不要修改项目。” 工具应先返回新演示目录和真实 workspace_id，检索主要资料应指向 `docs/login-design.md`。测试后保持设置，便于新对话核对。

真实使用时，直接告诉智能体要授权的项目绝对路径和当前任务。项目只读；不要授权含私人信息且不适合所选模型处理的目录。片段可能进入宿主使用的模型上下文，本插件不主动连接网络或 embedding 服务。

## 工具

| 工具 | 用途 |
| --- | --- |
| context_demo | 在插件缓存内创建新虚构演示项目并授权它 |
| context_open | 登记明确授权的绝对项目路径并扫描 |
| context_find | 按任务生成分层资料包和真实行号 |
| context_read | 返回指定行并记录当时内容指纹 |
| context_control | 固定/取消固定/排除/恢复单个索引文件 |
| context_status | 列出授权项目，或核对指定项目读取、设置和扫描状态 |

固定项单独列出，最多 5 个；排除最多 100 个。只有 context_read 返回过的文件版本才有读取记录，扫描及检索不会把全文标记为已读。变化根据 SHA-256 判断，不靠时间戳或模型记忆。

## 文件与状态边界

支持 UTF-8 Markdown、纯文本和常见代码格式，读取项目及嵌套 `.gitignore`，跳过隐藏项、常见凭据、符号/硬链接、依赖及构建目录。只支持常见 `*`、`**`、`?`、目录和 `!` 规则；转义与字符组不支持，相应目录停止检索。匹配采取保守子集，不等价于完整 Git 规则。不读取系统全局忽略文件。保护列表不能识别全部秘密，请只授权可分享资料。

预算：单文件 256 KiB、总文本 8 MiB、文件 500 个、访问目录项 4000 个、深度 12 层；单次返回最多 120 行。报告会列出跳过数量及预算边界，超限并不代表全项目无相关资料。来源为词面相关性及可解析路径引用，不是语义向量或代码调用图。不处理图片/PDF，不执行或修改项目代码。

缓存默认在 `~/.cache/agentic-hub-project-context/`，保存授权根目录、固定/排除、读取过的路径/行范围、时间与指纹，不持久保存项目正文。目录权限 0700，状态文件 0600；未加密。新对话共享本插件缓存。缓存损坏时保留原文件并报告，不自动清空。开发者可用 `PROJECT_CONTEXT_STATE_DIR` 指定隔离测试缓存。演示文件仅存在插件自己的缓存目录。

## 故障处理

- 找不到工具：确认通过扩展导入，并在新对话选中此插件；不要直接运行 Python 脚本后声称宿主接入成功。
- 运行时缺失：查看实际工具错误，确认 Python 3.9+ 和已有 Node 20+；不要修改 WorkSwarm 应用或全局安全设置。
- 文件不可读：核对路径、忽略/保护规则、文件大小、编码及扫描预算。被替换的根目录需重新授权。
- 无结果：缩小到明确术语或文件名。不要让智能体编造命中文档、阅读记录或图像理解。
